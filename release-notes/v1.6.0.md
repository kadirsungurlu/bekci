## Bekci 1.6.0

### Türkçe

**Yenilikler**
- **Kontrol noktaları arası bağlantı (mesh):** kontrol noktaları birbirine kalıcı TCP bağlantısıyla ping atar (varsayılan port `7480`, `MESH_ADDR`). Ping aralığı, kopukluk eşiği ve panel haberleşme aralığı Ayarlar > Kontrol noktaları'ndan verilir; kontrol noktası başına ezilebilir. Çerçeveler çift başına ayrı anahtarla imzalanır (HMAC).
- **Mesh olayı ve bildirimi:** bölünme, tek düğüm kopması, tek bağlantı ya da tek yönlü kopukluk tek bir olay ve tek bir bildirimle anlatılır; aynı anda her kontrol noktası için ayrı "çevrimdışı" bildirimi gitmez. Mesh olaylarını yalnızca yöneticiler görür.
- **Bağlantı matrisi ve topoloji şeması:** Ayarlar > Kontrol noktaları'nda canlı bağlantı matrisi ve şema; olay ayrıntısında olay anındaki şema. Telegram ve e-posta bildirimlerine şemanın görüntüsü eklenir.
- **Kısmi erişim kesintisi:** bir monitör yalnızca bazı konumlardan erişilemiyorsa ayrı bir "kısmi erişim kesintisi" olayı açılır; bildirimde tüm konumlar Başarılı/Başarısız satırıyla listelenir. Bağlantısı kopan konumun oyu kısmi kesinti açmaz. Yeni monitörlerde varsayılan olarak açıktır.
- **Ana sunucu konum adı:** Ayarlar > Genel'den panelin kendi konumuna ad verilir; olaylarda, konum kartında ve bildirimlerde bu ad görünür.
- **İkinci hat (OOB):** kontrol noktası ana hattı koptuğunda ikinci bir ağ arayüzünden (`PROBE_OOB_IFACE`) panele bağlanmaya devam eder; geçiş ve dönüş bildirilir, panelde hat rozeti gösterilir. İkinci hattaki konum kesinti kararına katılmaz. IP kilidi ikinci hat için ayrı bir IP kabul eder.
- **DNS kesintisinde bağlantı:** kontrol noktası panel adresinin son bilinen IP'sini saklar (`PROBE_STATE_DIR`), DNS çözülemezse onunla bağlanır.
- **Daha kısa denetim aralığı:** monitör denetim ve tekrar deneme aralığının alt sınırı 5 saniye. Sonuçlar veritabanına toplu yazılır (`BEAT_BATCH_MS`).
- **Sayfalı listeler:** Olaylar ve İşlem kaydı sayfa numaralı; toplam kayıt, sayfa boyu (25/50/100) ve sayfa adreste tutulur, geri tuşu çalışır.

**Değişiklikler**
- Kontrol noktasının çevrimdışı sayılması artık sabit 90 saniye değil: kopukluk eşiği x panel haberleşme aralığı (varsayılan 3 x 5 = 15 sn). Kalp atışı göndermeyen eski ajanlar için 90 saniye kuralı sürer.

**Bilinen eksikler**
- Mesh yedek bildirim kanalı (panel erişilemezken kontrol noktalarının kendi başına bildirim göndermesi), lider seçimi ve giden kutusu bu sürümde yok; mesh trafiği şifrelenmez, çerçeveler yalnızca HMAC ile imzalanır ve çift anahtarları süreyle yenilenmez.
- Telefonda bazı küçük görünüm sorunları (olay eylem düğmelerinin dizilimi, kaydırılabilir sekme ve matrislerde kenar ipucu) sonraki sürümde düzeltilecek.

**Güncellemeden önce**
- Veritabanı geçişleri (39-41) açılışta kendiliğinden uygulanır.
- Mesh için kontrol noktalarında `7480/TCP` portunu birbirine açın: [Kontrol noktaları arası bağlantı](https://bekci.app/docs/sunucu-ajani/#mesh). Port açılmazsa kontrol noktaları eskisi gibi çalışır, yalnızca mesh ölçülemez.
- Eski (1.5) kontrol noktaları yeni panelle çalışmaya devam eder; mesh ve ikinci hat için ajanları güncelleyin ([ajan güncelleme](https://bekci.app/docs/sunucu-ajani/#guncelleme)).
- Güncelleme: `docker compose pull && docker compose up -d` ([ayrıntılar](https://bekci.app/docs/guncelleme-yedek/#guncelleme)).

### English

**New**
- **Connections between check locations (mesh):** check locations ping each other over a persistent TCP connection (default port `7480`, `MESH_ADDR`). Ping interval, loss threshold and panel communication interval are set in Settings > Check locations and can be overridden per location. Frames are signed with a per-pair key (HMAC).
- **Mesh incident and notification:** a split, a single node going dark, a single link or a one-way loss is described by one incident and one notification, instead of a separate "offline" notice for every location. Mesh incidents are visible to admins only.
- **Connection matrix and topology diagram:** Settings > Check locations shows a live connection matrix and diagram; the incident detail shows the diagram at the time of the incident. Telegram and email notifications include an image of the diagram.
- **Partial reachability outage:** when a monitor is unreachable from only some locations, a separate "partial reachability outage" incident opens; the notification lists every location as Success/Failure. A location whose link is down does not open a partial outage. On by default for new monitors.
- **Main server location name:** name the panel's own location in Settings > General; incidents, the location card and notifications use it.
- **Second line (OOB):** when a check location's main line fails it keeps reaching the panel over a second network interface (`PROBE_OOB_IFACE`); failover and return are notified and the panel shows a line badge. A location on the second line does not vote in outage decisions. The IP lock accepts a separate IP for the second line.
- **Connecting during a DNS outage:** check locations keep the last known IP of the panel address (`PROBE_STATE_DIR`) and use it when DNS does not resolve.
- **Shorter check intervals:** the minimum monitor check and retry interval is 5 seconds. Results are written to the database in batches (`BEAT_BATCH_MS`).
- **Paged lists:** Incidents and Audit log are paged; total count, page size (25/50/100) and the page are kept in the address, and the back button works.

**Changes**
- A check location is no longer considered offline after a fixed 90 seconds: it is loss threshold x panel communication interval (default 3 x 5 = 15 s). The 90 second rule still applies to older agents that send no heartbeat.

**Known limitations**
- The mesh backup notification channel (check locations notifying on their own while the panel is unreachable), leader election and the outbox are not in this release; mesh traffic is not encrypted, frames are only signed with HMAC and pair keys are not rotated over time.
- Some minor phone layout issues (incident action button layout, edge hints on scrollable tabs and the matrix) will be fixed in a later release.

**Before updating**
- Database migrations (39-41) run automatically at startup.
- For the mesh, open port `7480/TCP` between check locations: [Connections between check locations](https://bekci.app/en/docs/server-agent/#mesh). Without it locations keep working as before; only the mesh cannot be measured.
- Older (1.5) check locations keep working with the new panel; update the agents for the mesh and the second line ([updating agents](https://bekci.app/en/docs/server-agent/#update)).
- Update: `docker compose pull && docker compose up -d` ([details](https://bekci.app/en/docs/updates-backups/#update)).
