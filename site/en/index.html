Uptime and server monitoring, in one tiny container

Bekci watches your websites, APIs and servers from a single dashboard and tells you the moment something breaks. Uptime checks, server metrics, status pages and alerts — all in about 15 MB of RAM.

Get started See screenshots 
$ docker run -d --name bekci -p 8080:8080 -v bekci-data:/data kadirsungurlu/bekci

Then open http://your-server:8080 and create the first admin account.

Agent security

Built for the servers you care about most

The agent runs on every server you monitor, so it's designed to run with minimal privileges and never change itself behind your back.

  • Tokens are stored as hashesA token is shown exactly once; the dashboard never keeps it in plain text.
  • IP lockThe first connecting IP is pinned (full IPv4 address, IPv6 /64). A stolen token is useless from any other machine.
  • Pinned, SHA-256-verified binaryThe binary is checked against the SHA-256 hash embedded in the install command and rejected on mismatch. The agent never updates itself, so even a compromised dashboard can't push new code to your servers.
  • Token never shows up in the process listIt never appears on a command line (ps); it lives only in a config file with 0600 permissions.
  • Hardened containerAll Linux capabilities dropped (--cap-drop ALL), no-new-privileges, a 256 MB memory cap and a process limit.
  • No plain HTTP by defaultThe agent refuses to connect to a dashboard that isn't served over HTTPS unless you explicitly allow it.
Structure of the Linux install command
sh <<'UPTIME_KURULUM'
set -e
# the token lives in a root-only file
install -m 600 /dev/null /etc/uptime-agent.env
cat > /etc/uptime-agent.env <<'UPTIME_ENV'
PROBE_SERVER=https://bekci.example.com
PROBE_TOKEN=upr_…
UPTIME_ENV
# hardened container; binary verified via SHA-256
docker run -d --name uptime-agent \
  --cap-drop ALL --security-opt no-new-privileges \
  --memory 256m --pids-limit 200 \
  --env-file /etc/uptime-agent.env …
UPTIME_KURULUM
Install

Up and running in a minute

Runs on any Linux server with Docker. 1 vCPU, 512 MB of RAM (1 GB recommended) and 10 GB of disk are plenty.

1

One Docker command

The quickest way to try it, or to run it behind the reverse proxy you already have (Caddy, Traefik, Nginx).

terminal 
docker run -d --name bekci --restart unless-stopped \
  -p 8080:8080 -v bekci-data:/data \
  -e BASE_URL=https://bekci.example.com \
  kadirsungurlu/bekci
  • BASE_URL is your public URL; notification links and agent install commands use it.
  • Prefer PostgreSQL? Point DATABASE_URL at your own server, or use the :postgres image with embedded PostgreSQL 18.
2

Coolify

On Coolify, add Bekci as a Docker image:

  • Image kadirsungurlu/bekci, port 8080, health check /healthz.
  • Persistent storage: /data (as a Volume). If you bind-mount a host directory instead, it must be owned by uid 1000.
  • On updates, the new container waits for the old one to stop, then takes over within a second or two — no duplicate checks, no double alerts.

On first launch, you'll be asked to create an admin account.

3

Docker Compose + Caddy (automatic HTTPS)

A permanent setup on a fresh server: Caddy obtains and renews Let's Encrypt certificates on its own. Point your domain's DNS at the server and open ports 80 and 443.

docker-compose.yml 
name: bekci
services:
  bekci:
    image: kadirsungurlu/bekci:latest
    restart: unless-stopped
    stop_grace_period: 30s
    environment:
      BASE_URL: https://bekci.example.com
      TZ: UTC
    volumes:
      - bekci-data:/data
  caddy:
    image: caddy:2-alpine
    restart: unless-stopped
    depends_on:
      bekci:
        condition: service_healthy
    ports: ["80:80", "443:443", "443:443/udp"]
    volumes:
      - ./Caddyfile:/etc/caddy/Caddyfile:ro
      - caddy-data:/data
      - caddy-config:/config
volumes:
  bekci-data:
  caddy-data:
  caddy-config:
Caddyfile 
bekci.example.com {
	encode zstd gzip
	header >Strict-Transport-Security "max-age=31536000"
	reverse_proxy bekci:8080 {
		# Stream live updates (SSE) without buffering
		flush_interval -1
	}
}
terminal 
docker compose up -d

Replace bekci.example.com with your own domain, then open it over https://.

FAQ

Frequently asked questions

Is Bekci free?

Yes. Bekci is self-hosted: no license fees, no subscription, no paid tiers. The only cost is the server you run it on.

Is the interface available in English?

Not yet. The UI is in Turkish today, including notifications and date formats — English UI is coming soon. Commands, paths and settings are the same in both languages, so everything on this page works as-is.

Which database does it use?

SQLite by default — no extra services, and the lightest option. If you'd rather use PostgreSQL, point DATABASE_URL at your own server or run the kadirsungurlu/bekci:postgres image with embedded PostgreSQL 18 (about 200 MB of extra RAM).

Data can't be moved between the two images, so pick one up front.

What are the system requirements?

At least 1 vCPU, 512 MB of RAM (1 GB recommended) and 10 GB of disk. The image is built for linux/amd64 and linux/arm64. Bekci itself uses around 15 MB of RAM with 10 monitors and 3 servers.

Can I monitor Windows servers?

Yes. The server agent runs on Linux (amd64, arm64) and Windows (amd64). On Windows, paste the command from the dashboard into PowerShell opened with Run as administrator; the agent installs as a Windows service that starts automatically.

On Windows, load average is approximated, and temperature and Docker containers aren't collected. Bekci itself (the dashboard) runs on Linux with Docker.

Where is my data stored?

Entirely on your server: monitors, measurements, incidents and users live in the SQLite database on the /data volume (or in your own PostgreSQL). With SQLite, a backup is written to /data/backups/ every night — we recommend copying that folder off the server too.

How do I update?

Take a backup, then pull the new image and recreate the container. With Compose:

docker compose pull && docker compose up -d

If a new version changes the database schema (SQLite), Bekci takes an automatic backup first and won't migrate if that backup fails. To pin a version or roll back, use version tags such as kadirsungurlu/bekci:1.2.3.

Is there a mobile app?

There's no app-store app, and you won't miss it. Bekci is a PWA: on iPhone, open it in Safari → Share → Add to Home Screen; on Android, use Chrome → Install app. It launches like a native app and updates live.
