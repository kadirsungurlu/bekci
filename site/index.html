Siteleriniz ve sunucularınız için tek nöbetçi

Bekci; web sitelerinizi, API'lerinizi ve sunucularınızı tek panelden izler, bir şey ters gittiğinde sizi hemen haberdar eder. Uptime kontrolleri, sunucu metrikleri, durum sayfaları ve bildirimler — hepsi ~15 MB RAM ile.

Ajan güvenliği

Sunucularınıza kurduğunuz ajan, kapınızdaki bekçi kadar güvenilir olmalı

Ajan, izlediğiniz her sunucuda çalışır. Bu yüzden baştan en az yetkiyle ve kendi kendine hiçbir şey değiştirmeyecek şekilde tasarlandı.

  • Token'lar özet (hash) olarak saklanırToken yalnızca bir kez gösterilir; sunucuda açık hâli tutulmaz.
  • IP kilidiİlk bağlantının IP'si sabitlenir (IPv4 tam adres, IPv6 /64). Token çalınsa bile başka bir makineden kullanılamaz.
  • SHA-256 ile sabitlenmiş sürümProgram komuttaki SHA-256 özetiyle doğrulanır, uyuşmazsa kurulmaz. Ajan kendini güncellemez; ana sunucu ele geçirilse bile sunucularınıza kendiliğinden yeni program inmez.
  • Token süreç listesinde görünmezHiçbir komut satırında (ps) yer almaz; yalnızca 0600 izinli ayar dosyasında durur.
  • Sertleştirilmiş konteynerTüm Linux yetkileri düşürülür (--cap-drop ALL), no-new-privileges, 256 MB bellek ve süreç sınırı.
  • Şifresiz bağlantıya varsayılan hayırAna sunucu HTTPS değilse ajan bağlanmaz; yalnızca açıkça izin verirseniz çalışır.
Linux kurulum komutunun yapısı
sh <<'UPTIME_KURULUM'
set -e
# token yalnızca root'un okuyabildiği dosyada
install -m 600 /dev/null /etc/uptime-agent.env
cat > /etc/uptime-agent.env <<'UPTIME_ENV'
PROBE_SERVER=https://bekci.ornek.com
PROBE_TOKEN=upr_…
UPTIME_ENV
# sertleştirilmiş konteyner; program SHA-256 ile doğrulanır
docker run -d --name uptime-agent \
  --cap-drop ALL --security-opt no-new-privileges \
  --memory 256m --pids-limit 200 \
  --env-file /etc/uptime-agent.env …

Kurulum

Bir dakikada çalışır hâlde

Docker olan her Linux sunucuda çalışır. En az 1 vCPU, 512 MB RAM (1 GB önerilir) ve 10 GB disk yeterli.

1

Docker ile tek komut

Denemek ya da zaten bir ters vekil (Caddy, Traefik, Nginx) kullanıyorsanız en kısa yol.

terminal 
docker run -d --name bekci --restart unless-stopped \
  -p 8080:8080 -v bekci-data:/data \
  -e BASE_URL=https://bekci.ornek.com \
  kadirsungurlu/bekci
  • BASE_URL: dış adresiniz; bildirim bağlantıları ve ajan kurulum komutları bunu kullanır.
  • PostgreSQL isterseniz: DATABASE_URL ile harici veritabanı ya da gömülü PostgreSQL 18 içeren :postgres imajı.
2

Coolify

Coolify kullanıyorsanız Bekci'yi Docker imajı olarak ekleyin:

  • İmaj kadirsungurlu/bekci, port 8080, sağlık kontrolü /healthz.
  • Kalıcı depolama: /data (Volume türünde). Sunucu klasörü bağlayacaksanız sahibi uid 1000 olmalı.
  • Güncellemede yeni konteyner eskisi kapanana kadar bekler, sonra 1–2 saniyede devralır; çift kontrol ya da çift bildirim olmaz.

İlk açılışta arayüz sizden yönetici hesabı oluşturmanızı ister.

3

Docker Compose + Caddy (otomatik HTTPS)

Boş bir sunucuya kalıcı kurulum: Caddy sertifikayı Let's Encrypt'ten kendisi alır ve yeniler. Alan adınızın DNS kaydı sunucuyu göstermeli, 80 ve 443 portları açık olmalı.

docker-compose.yml 
name: bekci
services:
  bekci:
    image: kadirsungurlu/bekci:latest
    restart: unless-stopped
    stop_grace_period: 30s
    environment:
      BASE_URL: https://bekci.ornek.com
      TZ: Europe/Istanbul
    volumes:
      - bekci-data:/data
  caddy:
    image: caddy:2-alpine
    restart: unless-stopped
    depends_on:
      bekci:
        condition: service_healthy
    ports: ["80:80", "443:443", "443:443/udp"]
    volumes:
      - ./Caddyfile:/etc/caddy/Caddyfile:ro
      - caddy-data:/data
      - caddy-config:/config
volumes:
  bekci-data:
  caddy-data:
  caddy-config:
Caddyfile 
bekci.ornek.com {
	encode zstd gzip
	header >Strict-Transport-Security "max-age=31536000"
	reverse_proxy bekci:8080 {
		# Canlı akış (SSE) tamponlanmadan iletilsin
		flush_interval -1
	}
}
terminal 
docker compose up -d

bekci.ornek.com yerine kendi alan adınızı yazın, ardından https:// ile açın.

SSS

Sıkça sorulanlar

Bekci ücretsiz mi?

Evet. Bekci kendi sunucunuzda çalışır; lisans ücreti, abonelik ya da ücretli plan yok. Tek maliyetiniz, onu çalıştırdığınız sunucu.

Hangi veritabanını kullanıyor?

Varsayılan olarak SQLite — ek servis gerekmez ve en hafif seçenek budur. İsterseniz DATABASE_URL ile kendi PostgreSQL sunucunuzu bağlayabilir ya da gömülü PostgreSQL 18 içeren kadirsungurlu/bekci:postgres imajını kullanabilirsiniz (yaklaşık 200 MB ek RAM).

İki imajın verisi birbirine taşınmaz; baştan birini seçin.

Sistem gereksinimi nedir?

En az 1 vCPU, 512 MB RAM (1 GB önerilir) ve 10 GB disk. İmaj linux/amd64 ve linux/arm64 içindir. Uygulamanın kendisi 10 monitör ve 3 sunucuda ~15 MB RAM kullanır.

Windows sunucularımı da izleyebilir miyim?

Evet. Sunucu ajanı Linux (amd64, arm64) ve Windows (amd64) üzerinde çalışır. Windows'ta panelden aldığınız komutu Yönetici PowerShell'e yapıştırmanız yeterli; ajan otomatik başlayan bir Windows hizmeti olarak kurulur.

Windows'ta yük ortalaması yaklaşıktır; sıcaklık ve Docker konteynerleri toplanmaz. Bekci'nin kendisi (panel) Linux üzerinde Docker ile çalışır.

Verilerim nerede duruyor?

Tamamen sizin sunucunuzda: monitörler, ölçümler, olaylar ve kullanıcılar /data birimindeki SQLite veritabanında (ya da kendi PostgreSQL'inizde) tutulur. SQLite kullanırken her gece /data/backups/ altına otomatik yedek alınır; bu klasörü sunucu dışına da kopyalamanızı öneririz.

Nasıl güncellerim?

Önce yedek alın, sonra yeni imajı çekip konteyneri yeniden oluşturun. Compose ile:

docker compose pull && docker compose up -d

Yeni sürüm veritabanı yapısını değiştirecekse (SQLite) Bekci önce otomatik bir yedek alır; yedek alınamazsa güncellemeyi uygulamaz. Belirli bir sürüme sabitlemek ya da geri dönmek için kadirsungurlu/bekci:1.2.3 gibi sürüm etiketlerini kullanın.

Mobil uygulaması var mı?

Ayrı bir mağaza uygulaması yok; gerek de yok. Bekci bir PWA'dır: iPhone'da Safari → Paylaş → Ana Ekrana Ekle, Android'de Chrome → Uygulamayı yükle. Ana ekrandan uygulama gibi açılır ve canlı güncellenir.
